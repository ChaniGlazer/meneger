# צ'אט אחד על אחד

אפליקציית צ'אט בזמן אמת, עם ממשק בעברית (RTL) — כוללת גם ניהול משימות, שעון נוכחות, ומסך ניהול למנהלות.

## מבנה הפרויקט

- `server/` — שרת Node.js (Express + Socket.IO) עם בסיס נתונים Postgres (מתארח ב-Supabase) וקבצים מועלים ב-Supabase Storage.
  - `index.js` — כל ה-REST endpoints וה-Socket.IO handlers.
  - `db.js` — יצירת הטבלאות ופונקציות הגישה ל-DB (דרך `pg`).
  - `upload.js` — קבלת קבצים (multer, בזיכרון) והעלאתם ל-Supabase Storage.
  - `auth.js` — גיבוב סיסמאות (scrypt) ויצירת טוקנים.
- `client/` — קליינט React (Vite) עם ממשק בעברית.
  - `App.jsx` — הרכיב הראשי, מנהל מסך (auth / inbox / chat / tasks / admin).
  - `TimeClock.jsx` — סרגל שעון הנוכחות שמופיע בראש האפליקציה.
  - `AdminDashboard.jsx` — מסך הניהול (למנהלות בלבד).
  - `api.js` — עטיפות `fetch` משותפות (עם/בלי טוקן אימות).

## הרצה מקומית

יש ליצור פרויקט Supabase חינמי (ראו "פריסה לפרודקשן" למטה) ולהעתיק את פרטי החיבור לקובץ `server/.env` (על בסיס `server/.env.example`).

בטרמינל אחד:

```
cd server
npm install
npm start
```

בטרמינל שני:

```
cd client
npm install
npm run dev
```

לאחר מכן פותחים דפדפן בכתובת `http://localhost:5173`. בכניסה הראשונה יש **להירשם** עם שם משתמש וסיסמה (לפחות 6 תווים); בפעמים הבאות אפשר פשוט **להתחבר**.

הסיסמאות נשמרות מוצפנות (scrypt + salt) בטבלת `users` ב-Postgres.

### שיחות (Inbox)

אחרי ההתחברות נפתח מסך **רשימת השיחות** - כל השיחות (דו-שיח וקבוצות) שהיו לך, ממוינות מהאחרונה שפעילה בה, עם תצוגה מקדימה של ההודעה האחרונה ותג מספרי לשיחות עם הודעות שלא נקראו. משם אפשר:
- **"שיחה חדשה"** - להקליד או לבחור מרשימת המשתמשים הרשומים עם מי לשוחח.
- **"קבוצה חדשה"** - לתת שם ולבחור כמה משתתפים רשומים, וליצור שיחה קבוצתית.

שיחה בין אותם משתתפים (דו-שיח או קבוצה) **ממשיכה בדיוק מהנקודה שבה הופסקה**, כולל אחרי סגירת הדפדפן או הפעלה מחדש של השרת - וגם אי אפשר להיכנס לשיחה שאינך חבר/ה בה, כי החברות נבדקת בצד השרת מול הטוקן המאומת שלך.

### התראות בתוך האפליקציה

כשמגיעה הודעה בשיחה שאינה פתוחה כרגע (למשל כשנמצאים במסך רשימת השיחות, או בתוך שיחה אחרת), תופיע הודעת טוסט חולפת, יתעדכן מספר ליד השיחה ברשימה, וכותרת הטאב תציג את מספר ההודעות שלא נקראו - כל זה עובד בכל דפדפן ובלי הרשאות מיוחדות.

**למה לא התראות מערכת אמיתיות (Web Notifications)?** משום ש-API הזה דורש "הקשר מאובטח" (HTTPS או localhost), ואם משתמשים באפליקציה משני מחשבים ברשת מקומית (למשל `http://192.168.x.x`) הדפדפן חוסם אותו ממילא. ההתראות בתוך האפליקציה עובדות בכל תרחיש, כולל שימוש משני מחשבים ברשת.

### משימות ("המשימות שלי")

הקישור **"המשימות שלי"** פותח לוח משימות מחולק לארבע עמודות סטטוס: לביצוע, בתהליך, להגהה, הושלם. הלוח מציג רק משימות שמשויכות אליך (`assigned_to`), עם כותרת, תיאור, תאריך יעד ותג עדיפות (נמוכה/בינונית/גבוהה). ניתן לעדכן את הסטטוס של משימה ישירות מהכרטיס שלה.

בכל יצירת משימה (`POST /api/tasks`) נוצרת אוטומטית **שיחת קבוצה מקושרת** (באותו מנגנון של "קבוצה חדשה"), עם יוצר המשימה והעובד/ת המשויכ/ת אליה כחברים. כפתור **"פתח צ'אט משימה"** בכרטיס המשימה פותח את השיחה הזו ישירות.

הנתונים נשמרים בטבלאות `tasks` ו-`time_logs`, עם REST endpoints מלאים ליצירה/עדכון/שליפה (`/api/tasks`, `/api/time-logs`) - ראו את `server/index.js` לרשימה המלאה.

### שעון נוכחות

סרגל קבוע בראש האפליקציה (בכל המסכים לאחר התחברות) מאפשר **כניסה** ו**יציאה** - כל לחיצה נשמרת כרשומה בטבלת `time_logs` (עם `clock_in`/`clock_out`). מצב הנוכחות משוחזר מהשרת אוטומטית גם אחרי רענון דף, כך שהוא לא תלוי ב-state מקומי בלבד.

### מסך ניהול (למנהלות בלבד)

משתמש/ת עם תפקיד `admin` רואה קישור נוסף **"מסך ניהול"**, המציג:
- **טבלת משימות מרוכזת** של כל העובדות, עם סינון לפי עובדת/סטטוס/עדיפות.
- **דוח שעות עבודה** מרוכז לפי עובדת וטווח תאריכים, עם כפתור **ייצוא ל-CSV**.

המסך וה-endpoints שמאחוריו (`/api/admin/*`) חסומים בצד השרת למי שאינו `admin` (מחזירים 403), לא רק מוסתרים בממשק.

**איך הופכים למנהל/ת?** אין כרגע מסך לניהול תפקידים. ה**משתמש/ת הראשונ/ה שנרשמ/ה** לאפליקציה מקבל/ת אוטומטית תפקיד `admin`. כדי להוסיף מנהלות נוספות יש לעדכן ידנית את העמודה `role` בטבלת `users` (ל-`'admin'`), למשל דרך ה-Table Editor של Supabase.

## פריסה לפרודקשן (חינמי)

הארכיטקטורה: **בסיס הנתונים וקבצי ההעלאה יושבים ב-Supabase** (לא תלויים בדיסק של אף שרת), וה**שרת + הקליינט** רצים יחד כשירות Render **אחד** — ה-Express server מגיש גם את קבצי ה-build של הקליינט, כך שכל התעבורה (API, WebSocket, והעמוד עצמו) עוברת דרך דומיין יחיד.

### 1. Supabase (בסיס נתונים + אחסון קבצים) — חינמי

1. הרשמה ב-supabase.com ויצירת פרויקט חדש.
2. **Database** → **Connect** (או Settings → Database) → להעתיק את ה-Connection string (URI). זה יהיה `DATABASE_URL`. מומלץ להשתמש ב-"Session pooler" (פורט 5432 או 6543 לפי מה שמוצג), ולהחליף את `[YOUR-PASSWORD]` בסיסמת ה-DB שנקבעה ביצירת הפרויקט.
3. **Storage** → יצירת bucket חדש בשם `uploads`, ולסמן אותו כ-**Public** (כדי שקישורי הקבצים יעבדו ישירות בלי אימות נוסף).
4. **Settings** → **API** → להעתיק את `Project URL` (זה `SUPABASE_URL`) ואת ה-`service_role` key (**לא** ה-anon key — זה `SUPABASE_SERVICE_KEY`. שימו לב: המפתח הזה עוקף את כל ההרשאות, אסור לחשוף אותו בקליינט, רק בשרת).
5. אין צורך להריץ שום SQL ידנית — השרת יוצר את כל הטבלאות אוטומטית בעליה הראשונה שלו (`init()` ב-`db.js`).

### 2. Render (שרת + קליינט יחד) — חינמי

1. render.com → **New** → **Web Service**, לחבר את ריפו ה-GitHub הזה.
2. **Root Directory**: להשאיר ריק (שורש הריפו).
3. **Build Command**: `cd client && npm install && npm run build && cd ../server && npm install`
4. **Start Command**: `node server/index.js`
5. **Environment Variables** (מתוך `server/.env.example`): `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_BUCKET=uploads`. את `PORT` לא צריך להגדיר — Render מזריק אותו אוטומטית. אין צורך ב-`VITE_API_URL`/`VITE_SOCKET_URL` כלל — הקליינט מדבר עם אותו origin שהגיש אותו.
6. Deploy. הכתובת שמקבלים (למשל `https://your-app.onrender.com`) היא הכתובת היחידה ששולחים לעובדות, וגם היחידה שצריך לאשר מול כל מסנן תוכן (כמו NetFree) אם רלוונטי.
7. הערה: ב-free tier השירות "נרדם" אחרי כ-15 דקות בלי תעבורה, וההתעוררות לוקחת כמה שניות בבקשה הראשונה. זה לא משפיע על שמירת הנתונים (הם ב-Supabase), רק על זמן התגובה הראשוני.

### בדיקה שהכל עובד

- `https://your-app.onrender.com/api/health` אמור להחזיר `{"ok":true}`.
- לפתוח את `https://your-app.onrender.com/` בדפדפן, להירשם, לשלוח הודעה עם קובץ מצורף, ולוודא שהקישור לקובץ עובד (זה מאמת שגם ה-DB וגם ה-Storage מחוברים נכון).
- לאחר דיפלוי מחדש — הנתונים וההודעות אמורים **להישאר**, כי הם ב-Supabase ולא בדיסק של Render.

## הרחבות עתידיות אפשריות

- מסך לניהול תפקידים (הענקת/שלילת הרשאת מנהל/ת) - כרגע רק ידני מול ה-DB.
- קריאה אמיתית ("נקרא/לא נקרא") עם מעקב בצד השרת, במקום ההיוריסטיקה הנוכחית בצד הקליינט.
- ניהול קבוצה: הוספה/הסרה של חברים אחרי היצירה, שינוי שם, עזיבת קבוצה.
- שליחת קבצים/תמונות.
- התראות מערכת אמיתיות (Web Push) - אפשרי בעתיד אם תוסיפו HTTPS.
- אינדיקציית "מקליד/ה", לכל שיחה.
- עריכה/מחיקה של הודעות ומשימות.
- דפדוף (pagination) בהיסטוריה ארוכה - כרגע מוגבל ל-100 הודעות אחרונות לכל שיחה.
- תוקף/פקיעה לטוקן ה-session (כרגע בתוקף עד להפעלה מחדש של השרת).
- עדכון אוטומטי של חברי שיחת המשימה כשמשנים את ה-`assigned_to` של משימה קיימת (כרגע נקבע רק ביצירה).
